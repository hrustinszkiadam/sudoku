# Multiplayer Sudoku

Online multiplayer sudoku on Cloudflare. One Worker serves the React SPA, the Hono API under `/api/*` and one `GameRoom` Durable Object per room. Live at **<https://sudoku.hrustinszki.com>**. See [PLAN.md](PLAN.md) for the full design.

- **Co-op**: everyone fills one shared board and sees each other's selected cell. Correct digits lock; wrong ones count as mistakes. Playing alone is single-player.
- **Race**: same puzzle, separate boards. Opponents see only progress counts. Score = finish time + 10 s × mistakes.
- **Daily**: one medium puzzle per UTC day, played in your own solo room, with a daily best-times table.
- **Leaderboard** per mode and difficulty, and your last 20 games on the home page.
- **Accounts (optional)**: sign in with GitHub or Google (Better Auth) to keep your history across devices. On first sign-in, your current guest history is linked to the account.

## Setup

Requirements: Node 22+, pnpm 12, a Cloudflare account.

```sh
pnpm install
cp .dev.vars.example .dev.vars                       # local secrets (Turnstile test keys)
pnpm db:migrate:local                                # create the local D1 schema
pnpm gen:puzzles -- --per-difficulty 500 --seed 42   # writes seeds/puzzles.sql (~90 s)
pnpm db:seed:local                                   # load the puzzles into local D1
pnpm dev                                             # http://localhost:5173
```

`seeds/puzzles.sql` is git-ignored; it is fully reproducible from `--seed`. `/dev/board` (development only) is a playground for the board component.

## Scripts

| Script | What it does |
| --- | --- |
| `pnpm dev` | Vite dev server; Worker, DOs and D1 run locally in workerd |
| `pnpm build` | Production build into `dist/` |
| `pnpm typecheck` | `tsc -b --force` over the client, worker, shared, node and test projects |
| `pnpm lint` / `pnpm format` | Biome check / fix |
| `pnpm test` | All Vitest projects: `unit` (Node) and `workers` (workerd) |
| `pnpm test:unit` / `pnpm test:workers` | One project only |
| `pnpm test:coverage` | Unit tests with coverage of `src/shared` |
| `pnpm test:e2e` | Playwright against a dev server (seed local D1 first; needs network for the Turnstile script) |
| `pnpm run deploy` | Build and `wrangler deploy`. Use `pnpm run deploy`, because `pnpm deploy` is a built-in pnpm command |
| `pnpm gen:puzzles` | Offline puzzle generator; writes `seeds/puzzles.sql` |
| `pnpm db:generate` | Generate a SQL migration from the Drizzle schema |
| `pnpm db:migrate:local` / `:remote` | Apply D1 migrations |
| `pnpm db:seed:local` / `:remote` | Load `seeds/puzzles.sql` into D1 (idempotent) |
| `pnpm cf-typegen` | Regenerate `worker-configuration.d.ts` after changing `wrangler.jsonc` |

## Layout

```text
src/shared/      runtime-agnostic: sudoku core (solver, grader, generator), protocol (Zod), constants, names
src/worker/      Hono app (routes, middleware, Drizzle queries) and the GameRoom DO (room/)
src/client/      React app: routes, components, Zustand stores, partysocket wrapper
scripts/         offline puzzle generator
test/            Worker/DO tests (@cloudflare/vitest-plugin)
e2e/             Playwright tests
migrations/      D1 SQL migrations (generated by drizzle-kit)
```

## Decisions worth knowing

- **Solution never leaves the server.** Snapshots come from one whitelisting function (`toClientSnapshot`), and `test/leak.test.ts` checks every message type in both modes.
- **Daily puzzle**: one *medium* puzzle per UTC day (`daily_puzzles.date` is the key). A cron at 00:05 UTC makes sure today's and tomorrow's exist; `GET /api/daily` also creates one on demand. Each player gets a deterministic solo co-op room for the day.
- **Rate limits**: room creation 10/min per user, guest sessions 20/min per IP (loopback is exempt so local dev and e2e aren't throttled), and a per-socket token bucket of 20 burst / 10 per second in the DO.
- **Newer tab wins**: the DO sends an explicit `replaced` error before closing the old socket with code 4000, because some proxies drop server close codes.
- **Testing package**: `@cloudflare/vitest-pool-workers` was renamed to `@cloudflare/vitest-plugin` (same API); this repo uses the new name.

## Deploying

The Worker is served on the custom domain `sudoku.hrustinszki.com` (`routes` in `wrangler.jsonc`; Cloudflare manages the zone, so deploy creates the DNS record and certificate).

One-time setup:

```sh
npx wrangler login
# D1 database (already created; the id is in wrangler.jsonc)
npx wrangler d1 create sudoku
# Turnstile widget for the domain; put its sitekey in wrangler.jsonc vars.TURNSTILE_SITE_KEY
npx wrangler turnstile widget create sudoku --domain sudoku.hrustinszki.com --mode managed
npx wrangler secret put SESSION_SECRET          # e.g. `openssl rand -hex 32`
npx wrangler secret put TURNSTILE_SECRET_KEY    # the widget's secret
npx wrangler secret put BETTER_AUTH_SECRET      # e.g. `openssl rand -hex 32`
pnpm db:migrate:remote
pnpm gen:puzzles -- --per-difficulty 500 --seed 42 && pnpm db:seed:remote
pnpm run deploy
```

## Accounts (GitHub / Google sign-in)

Better Auth runs on D1 through the Drizzle adapter at `/api/auth/*`. Its tables are prefixed `auth_`; game identity stays in `users`, linked by `users.auth_user_id`. Each provider is enabled only when both its client id and secret are set, and the sign-in buttons appear automatically.

1. Create the OAuth apps:
   - GitHub: <https://github.com/settings/developers> → New OAuth App, callback URL `https://sudoku.hrustinszki.com/api/auth/callback/github`.
   - Google: Google Cloud Console → Credentials → OAuth client ID (Web), authorized redirect URI `https://sudoku.hrustinszki.com/api/auth/callback/google`.
2. Store the credentials as Worker secrets:

   ```sh
   npx wrangler secret put GITHUB_CLIENT_ID
   npx wrangler secret put GITHUB_CLIENT_SECRET
   npx wrangler secret put GOOGLE_CLIENT_ID
   npx wrangler secret put GOOGLE_CLIENT_SECRET
   ```

`BETTER_AUTH_SECRET` (any long random string) is required whenever the Worker is deployed. For local sign-in, create separate OAuth apps with `http://localhost:5173` callbacks and put their values in `.dev.vars`.

## CI/CD

`.github/workflows/ci.yml` runs install → typecheck → lint → unit tests → worker tests → build on every PR. On push to `main` it then applies remote D1 migrations and deploys. It needs two repository secrets (Settings > Secrets and variables > Actions):

- `CLOUDFLARE_ACCOUNT_ID`: the account id from `wrangler whoami`.
- `CLOUDFLARE_API_TOKEN`: create it at <https://dash.cloudflare.com/profile/api-tokens> with:
  - **Workers › Editor**, either for all Workers or just the `sudoku` Worker (deploys the code). Creating the Worker from scratch would need **Admin** instead.
  - **Workers Routes › Write** on the zone `hrustinszki.com` (keeps the custom domain).
  - **D1 › Edit** (the `migrations apply --remote` step).
